# 通用信息结构规则

v0.1 · 从好产品的共性里归纳出来，不依赖任何模板，所有应用都适用。

## 依据

**Mobbin 上 8 个类目各取一个头部产品，每个看 2 张主屏**（预览图）：

| 类目 | 产品 | 看的屏 |
|---|---|---|
| 效率 | Things 3 | 今天、一个项目 |
| 金融 | Revolut | 首页、转账 |
| 旅行住宿 | Airbnb | 房源详情（照片、位置与问答） |
| 运动 | Strava | 一次跑步的详情、讨论 |
| 冥想健康 | Headspace | 今天、探索 |
| 外卖 | Uber Eats | 首页、筛选结果 |
| 学习 | Duolingo | 学习路径（两个课程） |
| 记账分账 | Splitwise | 动态、一个群组的统计 |

**苹果官方设计指南（HIG）** 里讲信息组织的部分：当前版本的三条总原则是“层级、和谐、一致”；布局一章要求用渐进展开（先藏起来，需要时再出现），把相关的东西分组并留出空间，用对齐和缩进表达层级；常用的放最上面，进阶的默认收起。

**说明**：产品是我按“各类目里公认的头部”挑的，Mobbin 的工具不提供热度排名。每个只看了 2 张屏，样本不大，下面每条规则都写明在哪几个产品里看到，你可以按链接核对。

## 共性一览

| 共性 | 在哪些产品里看到 |
|---|---|
| 首页就是核心对象本身，不是数据看板 | Things（任务清单）、Duolingo（学习路径）、Headspace（今天要做的）、Uber Eats（餐厅） |
| 首页如果有摘要，只有一个数或一行字 | Revolut（余额一个数）、Duolingo（顶部一行小数字） |
| 同类的文字项是清单行，不是卡片 | Things、Splitwise、Airbnb 详情、Strava 详情 |
| 卡片只给“带图、能单独挑选”的对象 | Uber Eats（餐厅）、Headspace（课程） |
| 区块之间靠留白和细线分开，区块有标题 | Things、Airbnb、Strava、Splitwise 统计 |
| 每一行：一行主文字 + 一行灰色补充 + 右侧小号状态 | Things、Splitwise、Headspace |
| 状态用一小段彩色文字，不用大徽章 | Things（红色“today”）、Splitwise（橙色“You owe”） |
| 一屏只有一个主操作，要么浮动按钮，要么底部固定条 | Things（＋）、Splitwise（添加账目）、Airbnb（底部“查看可订日期”） |
| 次要操作是区块末尾的文字链接 | Strava（“添加目标”“查看全部”）、Airbnb（“显示更多”） |
| 长内容先收起，给“显示更多” | Airbnb、Things（“隐藏之后的项”）、Splitwise（“查看全部动态”） |
| 按有意义的维度分组，组名就是标题 | Things（“今晚”）、Headspace（“夜间”） |
| 详情页顺序：是什么 → 关键信息 → 补充 → 相关；操作固定在底部 | Airbnb、Strava |
| 空状态只占一行，不占一屏 | Revolut（“还没有交易”） |
| 统计是“大数字 + 一行标签”上下排，不用仪表盘 | Splitwise 统计 |
| 底部导航 3–5 个，每个是一件独立的事 | Revolut、Headspace、Strava、Splitwise |

## 规则

格式：如果…就… · 对 · 错 · 怎么查 · 报错怎么写。“错”的例子都取自千问做的“新家入住采购”。

### U1 首页就是核心对象

**规则**：首页第一屏最大的东西，是用户每次打开都要用的那个对象（清单、题目、行程、课程）。如果要有摘要，摘要只有一个数或一行字，放在标题下面。

- 对：Things 的“今天”打开就是任务清单；Revolut 首页只有一个余额数字。
- 错：首页第一块是“清单合计 ¥1218 + 还没买 + 已入手 + 25% 圆环”，四个数字占了三分之一屏，清单本身被挤到第五块。

**查**：首屏面积最大的区块，必须是规格里“核心对象”的那个清单或内容。
**报错**：“首屏最大的是‘清单合计’摘要。把它缩成标题下的一行‘4 件 · 已买 1 · ¥1218’，让商品清单成为首屏最大的区块。”

### U2 同一个事实一屏只说一次

**规则**：同一个数字或状态，一屏只出现一次。要在多处用到，选最靠近它含义的那一处。

- 对：Things 的截止日只出现在任务行的右侧。
- 错：“已买 1”出现了四次：标题下、摘要里“1/4 已入手”、圆环“25%”、筛选“已买 1”。

**查**：把一屏的文字拆成数字和短语，同一个值出现两次以上就报错。百分比和分数算同一个事实。
**报错**：“‘已买 1’出现了 4 次（标题下、摘要、圆环、筛选）。只保留标题下那一处，删掉摘要和圆环，筛选里去掉数字。”

### U3 同类的文字项排成清单，不包卡片

**规则**：一组同类的东西，如果主要是文字（任务、商品、账目、课程时段），排成清单：行与行之间一条细线，不加底色、不加阴影。只有带大图、能单独挑选的对象（餐厅、课程封面、房源）才用卡片。

- 对：Things、Splitwise 的清单都是细线分隔的行。Uber Eats 的餐厅是带大图的卡片。
- 错：每个商品都是一张白色大圆角卡片，四张摞在一起。

**查**：一屏里带底色或阴影的块超过 3 个，且它们是同一种东西 → 报错。
**报错**：“4 个商品行各自是一张卡片。改成一个清单：去掉每行的底色和圆角，行与行之间一条细线。”

### U4 区块靠留白和细线分开，每块有标题

**规则**：页面分成几块时，块与块之间用比块内更大的留白，或一条细线。每块有一个小标题。不用卡片当分区。

- 对：Airbnb 详情、Strava 详情都是“标题 + 内容 + 细线”一块接一块。
- 错：成员和邀请包成一张卡片，摘要包成一张卡片，和商品卡片混在一起，看不出哪些是分区、哪些是内容。

**查**：块间距必须至少是块内间距的 2 倍；用卡片包裹整个分区 → 报错。
**报错**：“‘成员’分区被包成了一张卡片。去掉底色，改成小标题‘一起买的人’加下面的头像，和上面用一条细线分开。”

### U5 一行最多三层，状态放右边

**规则**：清单的一行：一行主文字，最多一行灰色补充，右侧放小号状态或数值。超过三行的内容放进详情。

- 对：Things 的任务行“名称 / 所属项目 / 右侧‘4天后’”；Splitwise 的动态“谁做了什么 / 金额 / 时间”。
- 错：（这张图做得还可以）商品行“名称 / 备注 / 价格 × 数量”是三层，符合。

**查**：清单行里文字超过 3 行 → 报错。
**报错**：“‘双抽床头柜’这一行有 4 行文字。把‘购买链接’移到详情页。”

### U6 状态用小号彩色文字

**规则**：状态（今天到期、欠款、已约满）用一小段彩色文字，不用大徽章、不用底色块。颜色只用语义色：成功、提醒、错误。

- 对：Things 的红色“today”，Splitwise 的橙色“You owe $200”。
- 错：用大号彩色胶囊表示“已买”。

**查**：表示状态的元素有底色块且宽度超过一个字的 4 倍 → 警告。
**报错**：“‘已约满’是一个红色底的胶囊。改成红色小字，去掉底色。”

### U7 一屏一个主操作，底部只有一层浮动

**规则**：一屏只有一个实心的主按钮。它要么是浮动按钮，要么是底部固定条，二选一。底部导航不算操作，可以和浮动按钮并存，但不能再加第二个浮动的东西。

- 对：Things 只有一个＋；Airbnb 只有底部“查看可订日期”；Splitwise 是底部导航加一个“添加账目”。
- 错：同时有渐变“邀请朋友一起买”、黑色浮动“加入商品”、浮动胶囊底栏，还有右下角的圆形“成员”按钮，四个都在抢。

**查**：数实心按钮的个数；数底部浮动或固定的元素（不算导航）。前者大于 1 或后者大于 1 → 报错。
**报错**：“这屏有 3 个实心按钮：‘邀请朋友一起买’‘加入商品’‘全部’。保留‘加入商品’；‘邀请’改成标题右侧的头像入口；‘全部’改成普通的选中样式。”

### U8 次要操作是文字链接

**规则**：不常用的操作（邀请、查看全部、编辑、删除）放在区块标题右侧或区块末尾，用文字链接或图标，不用实心按钮。

- 对：Strava 的“添加目标”“查看全部目标”是区块末尾的文字链接。
- 错：“邀请朋友一起买”是一个占满宽度的渐变大按钮。

**查**：和 U7 一起查。
**报错**：同 U7。

### U9 长内容先收起

**规则**：一组内容超过 5 项，或一段文字超过 4 行，先显示一部分，末尾放“显示更多”或“查看全部”。

- 对：Airbnb 的“显示更多”；Things 的“隐藏之后的项”；Splitwise 的“查看全部动态”。

**查**：清单超过 8 项且没有分组或收起 → 警告；正文超过 6 行没有收起 → 警告。

### U10 按有意义的维度分组

**规则**：清单很长时按一个用户在意的维度分组（时间、状态、房间、项目），组名就是小标题。只用一个维度，不嵌套。

- 对：Things 按“今天 / 今晚”，Headspace 按“白天 / 夜间”。
- 采购清单可以按“待买 / 已买”分组，就不再需要顶部的筛选标签。

**查**：不强制。分组后组内不能再包卡片（见 U3）。

### U11 详情页的顺序固定

**规则**：详情页从上到下：是什么（名称、图）→ 关键信息（时间、价格、状态）→ 补充说明 → 相关的东西。主操作固定在底部。

- 对：Airbnb 房源、Strava 跑步都是这个顺序。

**查**：主操作不在底部 → 警告。

### U12 空状态只占一行

**规则**：某一块没有内容时，在原位置显示一行说明，最多附一个文字链接。不用整屏插图。整个应用打开的第一屏不能是空状态。

- 对：Revolut“还没有交易”只占一行。

**查**：第一屏是空状态 → 报错（已有）。空状态占了一屏一半以上 → 警告。

### U13 底部导航 3–5 个，每个一件事

**规则**：底部导航 3–5 个。每个回答一个不同的问题。两个导航显示的是同一批东西，就合并。只有一件事的应用，不要底部导航。

- 对：Headspace“今天 / 探索 / 我”。
- 错：采购清单的“我的清单 / 收到的”如果显示的是同一批清单，就该合并成一个，用分组区分。

**查**：导航数不在 3–5 → 警告。

## 拿这 13 条改“新家入住采购”

| 现在 | 按规则改 | 依据 |
|---|---|---|
| 标题下“4 件 · 已买 1” + 合计大卡片 + 圆环 | 只留标题下一行“4 件 · 已买 1 · 共 ¥1218” | U1、U2 |
| 成员卡片 + 渐变“邀请”大按钮 | 删掉，邀请改成标题右侧的头像，点开另一屏 | U7、U8 |
| 筛选“全部 4 / 待买 3 / 已买 1” | 删掉，清单按“待买 / 已买”分组 | U2、U10 |
| 每个商品一张卡片 | 一个清单，细线分隔；有商品图就放在行首的小方图里 | U3 |
| 黑色浮动“加入商品” + 浮动胶囊底栏 + 圆形成员按钮 | 只留“加入商品”；成员入口移到标题；底栏如保留就不浮动 | U7、U13 |

改完后，首屏的顺序是：标题和一行摘要 → 待买（3 件） → 已买（1 件） → 底部一个“加入商品”。

## 和苹果设计指南的对应

| 苹果的原则 | 对应的规则 |
|---|---|
| 层级：让人一眼看到重要的东西 | U1、U5、U7 |
| 渐进展开：先藏起来，需要时再出现；常用的放上面 | U8、U9、U11 |
| 分组：相关的放一起，组之间留空，用对齐和缩进表达层级 | U3、U4、U10 |
| 和谐：形状同心 | 细节规则 D01（圆角嵌套） |
| 一致：用熟悉的模式，减少学习成本 | U11、U13 |

## 哪些能自动查

| 规则 | 能不能查 | 难度 |
|---|---|---|
| U1 首屏最大区块是核心对象 | 能，需要规格里标明核心对象 | 中 |
| U2 同一事实只说一次 | 能，拆文字找重复值；百分比和分数要换算 | 中 |
| U3 清单不包卡片 | 能，数同类的带底色块 | 低 |
| U4 块间距是块内的 2 倍 | 能，量间距 | 中 |
| U5 一行最多三层 | 能 | 低 |
| U6 状态是小字 | 能，看底色块宽度 | 低 |
| U7 一个主操作、一层浮动 | 能 | 低 |
| U9 长内容收起 | 能 | 低 |
| U12 空状态 | 能（第一屏已有） | 低 |
| U13 导航个数 | 能 | 低 |
| U8、U10、U11 | 只能部分查，靠规则引导 | — |
