# 怎么读参考图（第 5 步）

目的：把“看图”变成一组选择题，答案写进 `style/visual.json`，脚本据此生成样式。你不用写样式，只要把题答对。

**先把图放大看。** 用高清图；每一题都去图上找一处具体的位置当依据，写进 `evidence`。找不到依据的题，重新看图，不要猜。

## 逐题怎么判断

**mode**　页面最大那块底色是亮还是暗。

**colors**　跑 `node scripts/palette.mjs runs/<name>`，从结果里取：面积最大的中性色是 ground；主按钮的底色是 accent（它可能就是黑或白）。不要自己估色值。

**surface**　找一组相关内容（比如一条课程、一段说明），看它周围：
- 什么都没有，只靠上下的空白或一条横线和别的内容分开 → `none`
- 它躺在一块和页面颜色不同的底色上 → `fill`
- 它被一圈线框住 → `border`
- 它下面有一圈模糊的影子，像浮起来 → `shadow`
- 常见错误：看到深色界面就默认每块内容都有一个灰色圆角块。先确认图上真的有。

**radius**　看容器或图片的四个角：尖的 → `square`；刚能看出一点圆 → `small`；明显的圆角 → `medium`；很圆 → `large`；两端是半圆 → `pill`。图上没有容器时看图片和大色块的角。

**control_radius**　看主按钮和输入框的角，判断方法同上。

**divider**　内容之间有没有贯穿的细横线。

**button**　主按钮是一整块实心颜色（`solid`），还是只有一圈线、中间透出底色（`outline`）。

**selected**　找一个“选中”的东西（今天的日期、当前的标签）：整块颜色反过来 → `invert`；变成强调色 → `accent`；只多一条下划线 → `underline`。

**density**　数首屏有几块内容。三四块、大片留白 → `airy`；十行以上 → `compact`；其余 `regular`。

**title.weight**　最大的标题和正文比有多粗：差不多 → `regular`；稍粗 → `medium`；明显很粗 → `bold`。

**label**　找分类用的小字（“ON-DEMAND”“今日任务”这类）：很小且字距拉得很开 → `caps-spaced`；普通小字 → `plain`。

**imagery**　大图占了画面三分之一以上 → `photo-led`；只有列表里的小图 → `thumbnails`；几乎没图 → `none`。

## 选参考时先想一件事

如果参考是 `photo-led`，而你拿不到真实图片，做出来会和参考差一大截——它的好看主要来自那些照片。这时要么换一个不靠图片的参考，要么照做并在 `imagery_available` 写 `false`、在交付说明里讲清楚。不要用表情或色块顶替大图。

## 答完之后

```bash
node scripts/style.mjs runs/<name>     # 生成 theme/theme.ts 和 app/style.css
```

之后用 `kit/` 里的零件拼界面。零件的样子由这些答案决定，你不需要、也不应该再给它们写样式。门禁会量你做出来的界面，和这里的答案对不上就不通过。
