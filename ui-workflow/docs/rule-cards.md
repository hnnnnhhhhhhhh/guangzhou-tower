# 规则卡：给弱模型照做的八条

草案 v0.1 · 待你和设计师审。只是规则，还没有改任何代码。

**怎么读**：每张卡是一件事。“紧”的卡，模型没有发挥空间，照做就行；“松”的卡，模型可以发挥，但有护栏。每张卡最后写明哪些已经有脚本、哪些还要做。

**规则的写法**（八张卡都按这个来，以后加规则也按这个来）：

- 写成“如果…就…”，不写原则。
- 给选项，不给开放题；给数字，不给形容词。
- 一条规则配一个检查；查不了的规则不写。
- 每条配一个对的例子、一个错的例子。
- 报错写成“把什么改成什么”。

**执行顺序**：R1 → R2 → R3 → R4 → R5 → R6 → R7 → R8。前一张卡的产物是后一张卡的输入。

## R1 · 需求不清楚就问，不许猜　【紧】

**管什么**：把用户的一句话变成一张填满的规格表。

**模型要做的**

1. 读用户原话，填下面这张表。每一栏只能填用户原话里**直接说了**的内容，并抄下原话作为依据。

   | 栏 | 填什么 |
   |---|---|
   | 给谁用 | 一类人 |
   | 核心动作 | 用户每次打开亲手做的那件事，一句话 |
   | 要保存什么 | 用户的动作会改变的数据 |
   | 有几种身份 | 一种 / 两种及以上（各叫什么） |
   | 东西是不是“拿来看的” | 是 / 不是（见 R5） |
   | 气质 | 从给定的词里选一个：安静 / 活泼 / 严肃 / 温暖 / 利落 |

2. 如果某一栏在原话里找不到依据，这一栏留空，不许编。
3. 如果有留空的栏，向用户提问。规则：
   - 一次最多问 3 个，按上表从上到下的顺序挑。
   - 每个问题给 2–4 个选项，外加“其他”。
   - 用户不答，就用默认值：给谁用＝“普通个人用户”；身份＝一种；气质＝“利落”。
4. 用了默认值的栏，在规格里标 `"assumed": true`。

**对**：用户说“做个记账的”。核心动作能从原话得到（记一笔）；“给谁用”找不到 → 问：“主要是谁在用？A 我自己 B 一家人一起 C 小店记流水”。

**错**：用户说“做个记账的”，模型直接写“面向年轻白领，支持预算、报表、多账本、汇率”。

**检查**

- 每一栏要么有原话依据，要么 `assumed: true`，要么有对应的提问记录。三样都没有 → 报错“‘给谁用’这一栏没有依据：删掉，或者向用户提问”。
- 交付说明里必须列出所有 `assumed: true` 的栏。

**现状**：规格表已有（`app-spec.json`），但没有“依据”和“assumed”这两项，也没有提问这一步。要新做。

## R2 · 每屏放哪些信息，照同类产品的清单　【紧】

**管什么**：一屏上该出现哪些信息。防止模型凭空加一堆统计卡片，也防止漏掉该有的。

**模型要做的**

1. 对规格里的每一屏，用 Mobbin 搜同类产品的同一种屏，取 3 个不同的产品。
2. 对每个产品，把这一屏上的信息逐项列出来，一行一项：`信息是什么 | 是文字、数字、状态、图还是操作`。只列看得见的，不推测。
3. 合并三份清单。3 个里有 2 个以上都有的，标“必有”；只有 1 个有的，标“可选”。
4. 自己这一屏的信息：
   - “必有”的每一项都要放。**要删**，必须写出用户原话里的哪句话说明不需要。
   - “可选”的默认不放。**要放**，必须写出它服务 R1 里的“核心动作”的哪一步。
   - 清单上没有的，默认不放。要放，同上。

**对**：课程列表这一屏，三个产品都有“时间、课程名、剩余名额、状态”→ 必有，全放。只有一个有“教练评分”→ 可选，不放。

**错**：三个产品的首页都没有“本周数据概览”，模型加了一块，理由是“让页面更丰富”。

**检查**

- 每屏有一份清单文件，列出每项的来源（哪几个产品有）。
- 屏幕上的每个信息项都能对到清单的一行；对不上 → 报错“‘本周数据概览’不在清单里：删掉，或者写明它服务核心动作的哪一步”。
- “必有”项缺失且没有删除理由 → 报错“清单里的必有项‘剩余名额’没有出现”。

**现状**：流程里有“查结构”这一步，但只要求“写下学到了什么”，没有逐项清单，也没有检查。要新做。读图列清单这一步依赖模型看图；更稳的做法是由强模型线下列好存库，线上只查。

## R3 · 交互流程照同类产品的步骤　【紧】

**管什么**：用户完成核心动作要走几步、每一步点什么、看到什么。

**模型要做的**

1. 用 Mobbin 的流程搜索，找同类产品完成同一件事的完整流程，取 2 个。
2. 把每个流程抄成步骤表：`第几步 | 用户做什么 | 屏幕上发生什么`。
3. 写自己的步骤表。规则：
   - 步数**不能多于**两个参考里较少的那个。
   - 每一步写明对应参考的哪一步。对应不上的步骤删掉。
   - 用户做了动作之后，屏幕上必须有看得见的变化，写在“屏幕上发生什么”里。
4. 每一步都要写“做错了会怎样”：输入不合格、条件不满足时显示什么。

**对**：参考里约课是 3 步（点课程 → 看详情 → 点预约，按钮变成“已预约”）。自己也是 3 步，一一对应。

**错**：参考是 3 步，自己做成 5 步（多了“选择预约类型”和“二次确认弹窗”），没有对应的参考步骤。

**检查**

- 自己的步数 ≤ 参考的较小步数，否则报错“约课流程有 5 步，参考最少 3 步：删掉没有对应参考的第 3、4 步”。
- 验收脚本由步骤表逐步生成：每一步的“用户做什么”变成一次点击，“屏幕上发生什么”变成一次断言。任何一步断言失败都不通过。
- “做错了会怎样”至少有一条对应的验收脚本。

**现状**：验收脚本已有，但由模型自己写；没有“照参考步骤表”这一层，也没有步数限制。要新做。

## R4 · 间距、字号、颜色由脚本量，模型不许自己定数　【紧】

**管什么**：所有视觉上的数。

**模型要做的**

1. 选一个视觉参考。规则：
   - 从 R1 的“气质”对应的候选里选（候选由设计师事先挑好；没有候选库时，自己在 Mobbin 找，并写明为什么它符合这个气质）。
   - 如果 R5 的结论是“没有真图”，不许选靠照片撑起来的参考。判断办法：把参考图里的照片遮住，剩下的还好看吗？不好看就换。
2. 把参考的 3 张屏交给脚本。脚本给回：
   - 颜色：底色、文字色、次级文字色、主按钮色。
   - 字号：聚成几档，各是多少。
   - 间距：页面边距、块内间距、块间间距。
   - 这些数已经靠到 4 的倍数上。
3. 对着参考图回答选择题（容器是 无 / 底色 / 描边 / 阴影；圆角是 直角 / 小 / 中 / 大 / 胶囊；等）。每题写出依据在哪张图的哪个位置。
4. 把脚本的数和选择题的答案交给样式生成脚本。**不许手改生成的样式，不许在屏幕文件里写任何数。**

**对**：脚本量出“标题 28、正文 17、块间距 32”，模型原样使用。

**错**：模型觉得“标题大一点更醒目”，写成 36。

**检查**

- 屏幕文件里出现颜色值或带单位的数 → 报错“第 42 行写死了 `16px`：删掉，间距由零件决定”。
- 脚本量产出的每一屏，和参考比**比例**（不比绝对值）：标题与正文的字号比、块间距与块内间距的比。差超过两成 → 报错“标题应是正文的 1.6 倍，现在是 1.2 倍”。
- 选择题的答案和产出对不上 → 报错“参考图上容器是直角，这屏有 4 个圆角块：清单行「19:00 全身…」等”。

**现状**：量颜色、选择题、样式生成、选择题与产出的核对，**已有**。量字号和间距的脚本、比例核对，**要新做**；截图测量有两三个像素的误差，背景复杂或字叠在图上时会不准。

## R5 · 要不要图：查表；需要就必须去找　【紧】

**管什么**：图片位放不放、放什么。

**模型要做的**

1. 回答：这个应用里的主要对象，本身是不是“拿来看的”？
   - 是：菜、景点、商品、作品、房子、人。
   - 不是：题目、单词、待办、时段、金额、打卡记录。
   - 拿不准时的判断：用户会不会因为它“长什么样”来做选择？会就是“是”。
2. 查表：

   | 是拿来看的 | 怎么做 |
   |---|---|
   | 是 | 每个对象一个图片位。**必须**调用搜图工具，用对象的名字加类别去搜 |
   | 不是 | 不加图片位。不为了“填满画面”加图 |

3. 搜到图之后逐张核对：图里是不是这个对象？不是就换下一张，最多试 3 张。
4. 3 张都不对，或者没有搜图工具：图片位留空，显示“暂无图片”，并允许用户以后自己上传。
5. 不许做的：用表情、图标、色块、渐变顶替内容图；用生成的图表示具体的地点、菜、人、商品。

**对**：行程应用，每个景点搜一张真实照片；“岚山 汤豆腐”搜了 3 张都不对 → 留空，标“暂无图片”。

**错**：行程应用，所有景点都放同一个鸟居表情。

**检查**

- 每个图片位要么有真实的图片地址和来源，要么明确标空。出现贴纸或色块 → 报错“景点‘清水寺’的图片位放的是贴纸：去搜图，搜不到就留空”。
- “不是拿来看的”应用里出现内容图片位 → 报错“题目不需要配图：删掉图片位”。
- 每张图记录来源和使用许可。

**现状**：图片位零件已有（没图时自动显示“暂无图片”）。判断表、搜图、核对、检查都**要新做**；搜图要接你们平台的工具，我这边没有。

## R6 · 先用组件，用不了才自己画　【紧】

**管什么**：界面上的每一个东西从哪来。

**模型要做的**

对要放的每一样东西，按顺序问三个问题，在第一个“有”的地方停下：

1. 零件库（`kit/`）里有没有？有 → 用它。
2. 组件库（Astryx）里有没有？有 → 用它，属性用命令现查，不凭记忆写。
3. 都没有 → 才自己画，并且必须先填一张**例外单**：

   ```
   要放的东西：________
   查过的零件：________、________（为什么不合适：________）
   查过的组件：________、________（为什么不合适：________）
   参考图里它在哪：________
   ```

每屏自己画的东西**最多 1 个**。它就是这一屏的记忆点（见 R7）。

**对**：要放一组可多选的时段格子。零件库有“多选格子”→ 直接用。

**错**：要放一个按钮，模型自己写了一个带渐变的按钮，没有查零件库。

**检查**

- 屏幕文件只能引入零件库、组件库和本应用自己画的那一个文件；出现裸标签或别的包 → 报错“第 18 行用了裸 `<div>`：换成零件 `Stack` 或 `Row`”。
- 每屏自己画的东西数出来大于 1 → 报错“这屏有 3 个自己画的零件，最多 1 个：把‘渐变按钮’换成零件 `Btn`”。
- 自己画的东西没有对应的例外单 → 报错。

**现状**：“屏幕只能引入零件和组件、不许裸标签”的检查**已有**。例外单、每屏最多一个的限制，**要新做**。

## R7 · 自己画的那一个：形状自由，数值不自由　【松】

**管什么**：每屏的记忆点，也就是唯一允许模型发挥的地方。

**模型可以自己决定的**

- 它是什么形状、怎么构图、有没有动效。
- 参考哪张图的哪一处（可以去看 Mobbin，可以自己想）。

**模型不可以自己决定的**

1. 数值：间距、字号、圆角、颜色只能用 R4 给出的那几档和那几个颜色变量。
2. 位置：它必须服务这一屏的核心动作（背单词的记忆点是那张卡，不是角落的装饰）。
3. 基础规则照守，全文在 `design-details.md`：
   - 圆角嵌套要同心：里层 = 外层 − 间距。
   - 一块东西只用一种方式和背景分开：底色、描边、阴影三选一。
   - 粗体稀缺：不用最粗的两档；一屏最多一处粗体。
   - 一屏一种字体。
   - 能点的东西至少 44 高；文字和背景的对比度达标。
4. 先看库里有没有现成的：如果设计师的记忆点库里有适合这种动作的，优先选一个，不自己画。

**对**：背单词那屏，把词卡画成“一叠卡露出后两张的边”。用的间距、圆角都是规定的档位。

**错**：首页角落加了一个旋转的 3D 地球，和核心动作无关；阴影、描边、渐变叠在一起。

**检查**

- 自己画的样式里出现规定之外的数或颜色 → 报错“`22px` 不在间距档位里：改成 20 或 24”。
- 同一元素既有描边又有阴影、字重用了最粗两档、混了衬线和无衬线 → 报错并指明元素。
- 触控大小、对比度不达标 → 报错。
- “它服务核心动作”这一条查不了，靠 R8 的并排图和人看。

**现状**：数值、分隔叠用、字重、字体、触控、对比度的检查**已有**，但目前只在整屏层面查，要把范围明确扩到自己画的那个文件。记忆点库**没有**，需要设计师提供。**这一张卡的质量最依赖模型本身**，是八张里最没把握的。

## R8 · 做完看图自查，按指令改，最多三轮　【紧】

**管什么**：交付前的最后一关。

**流程**

1. 脚本把每条验收场景点一遍，每屏截图。
2. 脚本检查并给出**修改指令**，一条指令只说一件事，格式固定：

   ```
   哪一屏 · 哪个元素 · 现在是什么 · 应该是什么 · 怎么改
   ```

   例：`课程列表 · 清单行「19:00 全身循环训练」· 圆角 16 · 应为直角 · 删掉这一行的自定义样式`

3. 模型逐条执行指令。**只改指令里提到的东西**，不顺手改别的。
4. 重新检查。最多 3 轮。
5. 3 轮后还有不通过的：停下，把剩余的问题原样列进交付说明，不许为了通过去改检查脚本、改选择题的答案、或者删验收断言。
6. 全部通过后，脚本拼出“参考 | 产出”的并排图。模型看图回答 3 个是非题，答案写进交付说明：
   - 第一屏最大、最重的东西，是用户此刻要做的那件事吗？
   - 遮住文字，能认出这是哪个应用吗？（认不出＝还是通用模板）
   - 和参考并排，有没有一眼看上去很突兀的地方？在哪？

**不许做的**

- 第一屏是空状态。示例数据必须相对“今天”生成，让第一屏有内容。
- 说“验证过”但没有跑过。

**检查**

- 脚本本身就是检查。
- 修改指令之外的文件被改了 → 警告，列出被改的文件。
- 第一屏是空状态 → 报错“打开的第一屏是空状态：让示例数据落在今天”。

**现状**：验收、截图、各项检查、第一屏检查、并排图，**已有**。把报错统一成“修改指令”的固定格式、三轮上限、“只改指令提到的东西”的核对、最后 3 个是非题，**要新做**。

| 卡 | 已有 | 要新做 |

| R1 澄清 | 规格表 | 依据与 assumed、提问 |

## 我没有把握的地方

- **R2、R3、R4 里“读图”的部分仍然靠模型**（列信息清单、抄流程步骤、答选择题）。对千问最稳的办法是把这三样挪到线下，由强模型加设计师做好存库，线上只查库。这样线上就完全不需要看图。
- **R4 的截图测量是近似的。**
- **R7 是松的，质量看模型。** 没有记忆点库时，千问自己画的东西大概率平庸。
- **八张卡都没有在千问上跑过。**
