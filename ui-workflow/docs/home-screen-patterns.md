# 首页怎么组织

v0.1 · 和 `universal-structure-rules.md` 配合使用。那一份讲每一屏的通用规则，这一份专讲首页：第一屏放什么、按什么顺序。

## 依据

在 Mobbin 上看了这些产品的首页（每个 2 张）：

Waymo、Nike Run Club、Duolingo、Tiimo、Things 3、Partiful、Shop、Apple Music、Headspace、Airbnb、AllTrails、Uber / Uber Eats、Luma、Medium、Nike。

Etsy 的首页在 Mobbin 上没搜到。Luma 的“首页”搜索第一次返回的是 Partiful，因为两者是同类产品，一起放进来了。

---

## 结论：好产品的首页只有四种

先判断应用属于哪一种，再按那一种的顺序排。不要四种混在一起。

| 类型 | 用户打开时心里想的 | 第一屏最大的东西 | 例子 |
|---|---|---|---|
| **做事型** | “我现在就要做那件事” | 做那件事的入口 | Waymo“去哪？”、Nike Run Club 的“开始”、Things 的今日清单、Duolingo 的学习路径 |
| **继续型** | “我之前的事进展到哪了” | 我的下一件事 | Partiful“接下来”、Shop 的物流进度、Apple Music 的正在播放、Headspace 的今天 |
| **逛型** | “看看有什么” | 搜索 + 分类 + 内容 | Airbnb、AllTrails、Uber Eats、Luma 发现页 |
| **读型** | “有什么新的可看” | 内容流本身 | Medium、Nike 的故事 |

### 怎么判断（给模型的）

按顺序问，第一个“是”就停：

1. 用户每次打开做的是**同一件事**，而且**下一步是确定的**吗？（下一道题、今天的清单、开始跑步）→ **做事型**
2. 用户有**正在进行中的东西**吗？（订单、预约、计划、正在播放）→ **继续型**
3. 主要对象是一个**很大的目录**，用户要挑吗？（房源、餐厅、商品、步道）→ **逛型**
4. 主要是**看内容**吗？（文章、动态、故事）→ **读型**
5. 都不是 → **做事型**，把核心动作放在第一屏

## 四种首页各自的顺序

### 做事型

```
顶部：页面名或今天的日期；右侧最多 2 个图标
第一块：做那件事的入口（占首屏一半以上）
  - 输入型：一个大输入框（Waymo“去哪？”）
  - 启动型：一个大按钮（Nike Run Club“开始”）
  - 清单型：清单本身（Things）
第二块：最近的几条（Waymo 的最近地址）
其余：没有，或者很少
```

- Waymo：大字“你的车 13 分钟后到” → 大输入框“去哪？” → 两个快捷地址 → 最近两条 → 一张推广（在最下面）。
- Nike Run Club：整屏照片，正中一个大“开始”。
- Things：标题“今天” → 日程 → 任务清单。

**不要**：在入口上面放统计、欢迎语、推荐。

### 继续型

```
顶部：头像或页面名；右侧通知、搜索
第一块：我的下一件事（一个，最多两个）
  带时间、状态，和一个直接的操作
第二块：我的其他进行中的东西（清单）
第三块：推荐（可以有，放在后面）
最后：推广、引导（小的、可关掉）
```

- Partiful：“接下来”（两场活动，横排）→ “我主办的”（一场，带来宾数）→ “为你挑的”（清单）→ 推广卡片在最下面。
- Shop：最近一个订单（一行，带送达日期）→ 一条可关掉的提示 → “最近看过” → 店铺推荐。
- Apple Music 小组件：正在播放 → 最近播放（清单）。

**不要**：自己的东西为空时还占位置。没有进行中的东西，这一块直接不出现，下面的上移。

### 逛型

```
顶部：搜索框（第一屏最显眼的控件）
第二行：一排分类或筛选标签（可横滑）
主体：内容，按区块排
  每个区块：标题 + 右侧“查看全部”或箭头
  带图的对象：横排一条，或单列大图
  文字为主的对象：竖排清单
```

- Airbnb：搜索框（显示当前条件）→ 筛选标签 → 地图 → 房源大图。
- AllTrails：搜索框 → 分类标签（附近、适合孩子、适合狗）→ 一张大卡片（附近的一条步道）。
- Uber Eats：搜索框 → 分类图标一排 → “附近的店”（横排圆标）→ 每家店的商品（横排）。
- Luma 发现：“城市”（横排大图）→ “精选日历”（竖排清单）。

**注意节奏**：相邻两个区块换一种排法。Luma 是横排大图接竖排清单，Uber 是图标一排接圆标一排接商品卡一排。连续三个一模一样的横排会显得像模板。

**不要**：在搜索框上面放大横幅；把每个区块都做成一模一样的横排卡片。

### 读型

```
顶部：品牌字或页面名；右侧通知
第二行：2–3 个文字 Tab（为你推荐 / 关注 / 精选）
主体：内容流，一条一条，细线分隔
  每条：来源一行（小）→ 标题（粗）→ 摘要一两行（灰）→ 互动数（小）
  有图：右侧小方图，或上方大图，全流统一一种
```

- Medium：品牌字 → “为你推荐 / 精选” → 文章流，细线分隔，右侧小图。
- Nike 故事：“为你推荐” → 大图 + 分类小字 + 标题。

**不要**：把每条都包成卡片；在流的开头放统计。

## 四种首页都遵守的

| 规则 | 依据 |
|---|---|
| 顶部最多：左边一个（头像、返回或页面名），右边两个图标 | 全部 |
| 不放品牌口号、欢迎语 | 全部 |
| 第一屏只有 2–3 个区块 | 全部 |
| 区块标题右侧可以有“查看全部”，不放其他按钮 | Partiful、Luma、Uber、Nike Run Club |
| 顺序：我的 / 现在的 → 附近的 / 个性化的 → 通用推荐 → 推广 | Partiful、Shop、Waymo、Apple Music |
| 推广和引导：小的、可以关掉、不在第一块 | Airbnb、Apple Music、Shop |
| 自己的东西为空时，那一块不出现 | Shop、Partiful |
| 带图的对象用图说话，文字少；文字对象用清单，不配假图 | Luma、Uber、Medium |
| 相邻区块换排法 | Luma、Uber、Partiful |
| 首页是底部导航的第一个 | 全部有底部导航的 |

## 拿这套方法看两个例子

### “新家入住采购”（千问的产出）

- 判断：每次打开做的是同一件事（勾掉买好的），下一步确定 → **做事型**，而且是清单型。
- 按做事型的顺序：标题和一行摘要 → 清单本身。
- 千问的版本是“继续型 + 逛型 + 数据看板”混在一起：合计看板、成员卡片、搜索筛选、清单、两层浮动按钮。改成做事型后，第一屏就是清单。

### “天天练约课”

- 学员端判断：有进行中的东西（约好的课）→ **继续型**。
  - 第一块：“下一节课”——时间、课程名、还有几小时，和一个“取消”或“查看”。
  - 第二块：这周的课，按天选（日期条 + 清单）。
  - 没有约课时，第一块不出现，日期条和课程清单直接上移。
- 教练端判断：每次打开做的是同一件事（看今天谁来、开课）→ **做事型**。
  - 第一块：今天的课，清单。
  - 排课是另一个入口，不在首页第一屏。
- GPT 和我之前做的版本，学员端首页都是“日期条 + 当天课程”，漏了“下一节课”这一块。这是按继续型能补上的。

## 能自动查的

| 检查 | 怎么查 |
|---|---|
| 规格里写明首页类型 | 规格多一栏“首页类型”，四选一，并写出判断依据 |
| 第一屏最大的区块符合类型 | 做事型：入口或清单；继续型：我的下一件事；逛型：搜索框在最上；读型：内容流 |
| 第一屏区块数 2–3 | 数首屏可见的区块标题 |
| 顶部右侧最多 2 个图标 | 数 |
| 推广不在第一块 | 标了“推广”的区块不能是首屏第一个 |
| 空的个人区块不出现 | 用空数据跑一遍，个人区块不应渲染 |
| 相邻区块换排法 | 连续 3 个区块都是横排 → 警告 |
