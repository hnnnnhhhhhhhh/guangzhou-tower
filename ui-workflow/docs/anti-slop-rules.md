# 防“AI 味”的通用规则

v0.1 · 和 `universal-structure-rules.md`（信息结构）、`design-details.md`（细节）配合使用。这一份管的是“一眼看上去就是 AI 做的”那些东西。

## 依据

- **你挑的好产品**，在 Mobbin 上各看了 2 张主屏：Luma、Tiimo、AllTrails、Nike Run Club、Apple Music、Medium、Etsy、Shop、Waymo；加上一轮看过的 Uber Eats、Duolingo、Airbnb。Nike 主应用这次没看。
- **你给的 Tab 选型图**（六种 Tab 的使用场景、优缺点）。
- **千问实际产出里反复出现的问题**。

每条规则都写了“好产品怎么做”和“AI 常见做法”，可以对照截图核对。

---

## 一、颜色

### A1 不用跨色相的渐变

**规则**：按钮、文字、卡片、背景都不用跨色相的渐变（蓝→紫、粉→橙、青→绿）。同一色相内的深浅过渡可以用，但只用在大面积背景上。

- 好产品：没有一个按钮是渐变的。AllTrails 是一个浅绿实底；Etsy 是近黑实底；Luma 的背景是从封面图取的单一色调，深浅变化，不换色相。
- AI 常见：蓝紫渐变的主按钮、彩虹渐变的标题字。
- **例外**：表示数据的渐变可以用，比如 Nike Run Club 地图上按配速从绿到红的路线。

**查**：所有 `linear-gradient` / `radial-gradient`，取首尾两色的色相，差超过 30° → 报错（数据图表除外）。
**报错**：“‘邀请朋友’按钮用了蓝→紫渐变。改成主强调色实底。”

### A2 一个强调色，用在少数地方

**规则**：全应用只有一个强调色。它只用在：主按钮、当前选中、少数关键数字。其余都是黑白灰。状态色（成功、提醒、错误）另算，只用在表示状态的文字上。

- 好产品：Apple Music 的红只出现在当前标签、收藏星、“开始”按钮；Medium 的绿只在一个浮动按钮上；Etsy 的绿只在价格上。
- AI 常见：每个区块一个颜色，每个图标一个颜色。

**查**：取页面上所有非灰色（饱和度大于 15%）的颜色，按色相聚类；除状态色外超过 1 类 → 报错。强调色面积超过首屏 10% → 警告。
**报错**：“这屏出现了 3 种强调色：蓝（按钮）、紫（头像）、橙（标签）。只保留蓝，头像和标签改成灰。”

### A3 不在每一行前面放彩色方块图标

**规则**：清单行前面要么放真实的内容图（封面、头像、商品图），要么不放。不放“浅色圆角方块里一个彩色图标”。

- 好产品：Apple Music 的“歌单 / 艺人 / 专辑”是单色线条图标，没有底色块；Things 的任务行前面只有勾选框。
- AI 常见：每一行前面一个不同颜色的圆角方块，里面一个图标。

**查**：清单行开头是带底色的方块且里面是图标而不是图片，同一屏超过 2 个 → 报错。
**报错**：“清单的 5 行各有一个彩色方块图标。去掉方块底色，图标改成单色线条，或者整个去掉。”

## 二、字

### B1 一屏一个重字

**规则**：一屏只有一处用最重的字重，就是这屏的主角。其余标题用中等字重，正文用常规。

- 好产品：Nike Run Club 只有“2.02”是粗斜体；AllTrails 的步道名是常规字重的大字；Medium 只有文章标题是粗体。
- AI 常见：标题、卡片名、按钮、标签、数字全是粗体。

**查**：已有（细节规则 D05）。

### B2 字号最多四档

**规则**：一屏的字号最多四档：主角、标题、正文、辅助。

- 好产品：AllTrails 详情页只有三档：步道名、数值、标签。

**查**：统计一屏不同的字号，超过 4 → 报错。
**报错**：“这屏有 6 种字号。把 15 和 16 合并成 16，13 和 12 合并成 13。”

### B3 装饰字体只用一处

**规则**：衬线、手写、斜体粗体这类有性格的字体，一屏最多用在一处（标题或一个大数字）。

- 好产品：Tiimo 只有“Wednesday”是衬线；Medium 只有品牌字是衬线；Nike Run Club 只有大数字是粗斜体。

**查**：已有（细节规则 D06）。

## 三、数字

### C1 数值和标签上下排，标签小而灰

**规则**：一组统计是“大数值 + 下面一行小号灰色标签”，排成两列或三列的网格，不包卡片。单位比数值小一档。

- 好产品：AllTrails“5.8 mi / 长度”“764 ft / 爬升”两列；Nike Run Club 三列，不加任何底色。
- AI 常见：一排三张小卡片，每张一个图标、一个数、一个标签。

**查**：统计格有底色或阴影 → 报错；单位和数字同字号 → 报错（细节规则 D04）。
**报错**：“3 个统计各包了一张卡片。去掉卡片，改成‘数值在上、标签在下’的三列。”

### C2 不为了好看加图表

**规则**：一个比例（1/4、25%）只用一种方式表达，优先用文字。进度环、仪表盘只给“这个比例就是核心”的应用（运动目标、学习进度）。

- 好产品：Shop 的物流进度是一条细线；Etsy 的评分是“4.8 ★”加几条细线。
- AI 常见：任何有比例的地方都放一个进度环。

**查**：同一个比例既有文字又有图形 → 报错（信息结构 U2）。

## 四、容器

### D1 不是每块都要卡片

**规则**：见信息结构 U3、U4。补充：卡片只给“带图、能单独挑选的对象”和“必须和周围区分开的一块”。整屏卡片不超过 3 张。

- 好产品：Apple Music、Medium、Etsy 主体都是细线分隔；Waymo 只有搜索框和一张推广是卡片。
- AI 常见：灰底上摞七八张白色圆角卡片。

### D2 阴影、描边、底色三选一

**查**：已有（细节规则 D02）。

### D3 不用“玻璃”和“光晕”当默认

**规则**：毛玻璃、发光、彩色光晕、模糊色团只在参考风格明确使用时用，而且只用在浮在内容上方的东西（底栏、弹层）。

- 好产品：Luma 和 Apple Music 的底栏是半透明的；内容区没有。
- AI 常见：背景放两团模糊的彩色光晕，卡片全是半透明玻璃。

**查**：内容区（不是浮层）出现 `backdrop-filter` 或模糊色团 → 报错，除非风格文档写明使用。

## 五、按钮

### E1 一个实底主按钮，其余降级

**规则**：一屏一个实底主按钮。第二个操作用浅灰底或描边，第三个及以后用文字或图标。

- 好产品：AllTrails“下载”浅绿实底 +“地图”浅灰底；Etsy“查看购物车”近黑实底 +“立即购买”“出价”描边；Luma“报名”白色实底 +“联系”“更多”半透明。
- AI 常见：三个并排的彩色实底按钮。

**查**：已有（信息结构 U7）。

### E2 按钮形状全应用统一

**规则**：所有按钮用同一种圆角（全圆或同一个圆角值）。不能这里胶囊、那里方角。

- 好产品：Etsy 全是胶囊；AllTrails 全是胶囊；Waymo 全是大圆角。

**查**：统计所有按钮的圆角，超过 1 种（不算图标按钮）→ 报错。

## 六、Tab

结合你给的选型图，按“用户心里在问什么”选 Tab，不按“看起来丰富”选。

### F1 先问清楚，再选 Tab

| 用户心里在问 | 用哪种 | 上限 | 好产品 |
|---|---|---|---|
| “我要去哪个功能” | 底部导航 | 3–5 个 | Apple Music 5 个、Tiimo 4 个、Luma 3 个 |
| “我想看哪类内容” | 顶部文字 Tab | 2–5 个 | Medium“为你推荐 / 精选”、Nike Run Club“排行 / 挑战” |
| “同一批东西，看哪种状态” | 分段控件 | 2–4 个 | 待付款 / 已完成 |
| “分类太多放不下” | 可横滑的 Tab 或筛选标签 | 不限，但高频的放前面 | Shop“优惠 / 关注 / 收藏”、Uber Eats 菜系 |
| “这里有事要我处理” | 带数字的 Tab | 只在真有待办时显示数字 | Etsy 购物车角标 |
| “大模块里还有子分类” | 顶部 + 底部双层 | 尽量不用 | — |

### F2 能不用 Tab 就不用

**规则**：

1. 只有一件核心的事的应用，不要底部导航。
2. 两个 Tab 显示的是同一批东西 → 合并，用分组区分（见信息结构 U10、U13）。
3. 一屏最多一层 Tab。不同时出现“顶部 Tab + 分段控件 + 筛选标签”。
4. 内容少于 8 项时，不需要“全部 / 待办 / 已完成”这种筛选 Tab，直接按状态分组。
5. 数字角标只表示“有事要处理”，不用来显示总数。“全部 12”不是角标该做的事。

- 好产品：Things 没有底部导航；Medium 的顶部只有两个文字 Tab，没有底色。
- AI 常见：底部导航 + 顶部 Tab + 一排胶囊筛选同时出现；只有 4 件商品也做“全部 4 / 待买 3 / 已买 1”。

**查**：一屏里 Tab 类控件（底部导航除外）超过 1 组 → 报错；筛选 Tab 所在的清单少于 8 项 → 警告；Tab 上的数字等于该 Tab 的条目总数 → 警告。
**报错**：“这屏同时有顶部 Tab 和胶囊筛选。只保留筛选；清单只有 4 项，筛选也可以去掉，改成按‘待买 / 已买’分组。”

### F3 Tab 长得要轻

**规则**：顶部 Tab 是文字，选中靠字重或下划线，不用彩色胶囊底。分段控件用浅灰底加白色选中块。

- 好产品：Medium、Nike Run Club 的顶部 Tab 都只是文字，选中的字更黑。

**查**：顶部 Tab 选中项是彩色实底 → 警告。

## 七、图标、图片和装饰

### G1 不用表情当图标

**规则**：界面上的功能图标用同一套单色线条图标。表情只在内容本身就是表情时出现（用户写的）。

- 好产品：都用单色线条图标。Shop 和 Waymo 偶尔在用户自己的内容里出现表情。
- AI 常见：区块标题前加一个表情，按钮里加一个表情。

**查**：界面固定文字（标题、按钮、标签）里出现表情 → 报错。

### G2 没有真图就不放图

**规则**：见细节规则 D07。补充：不放和内容无关的插画、吉祥物、3D 小物件来“填画面”。

- 好产品：Apple Music、Medium、Etsy 的图全是真实内容（封面、文章配图、商品）。
- AI 常见：空白处放一个 3D 插画或一个可爱角色。

### G3 不加装饰形状

**规则**：不加和内容无关的圆形、色块、波浪、光斑、网格背景。

- AI 常见：卡片右上角一个半透明的大圆。

**查**：没有文字、没有图片、不能点的带色元素 → 报错。

## 八、文案

### H1 不写空话

**规则**：不写“欢迎回来！”“让我们开始吧”“轻松管理你的 XX”这类不提供信息的句子。标题就是这一屏的名字，副标题只写真实的状态。

- 好产品：Waymo“你的车 13 分钟后到”；Shop“预计 8 月 3 日送达”；Things“今天”。
- AI 常见：“开启你的高效一天 ✨”。

**查**：维护一份空话清单（欢迎、让我们、轻松、开启、探索更多、一站式……），出现就报错。

### H2 示例数据要像真的

**规则**：示例内容用具体、合理的数据：真实的地名、合理的价格、普通的人名。不用“示例商品 1”“用户 A”“¥999”。

**查**：出现“示例”“测试”“XXX”、连续三个相同数字 → 报错。

## AI 味速查表

做完一屏，对着这张表过一遍。有任何一项，就还有 AI 味。

| 一眼能看出的 | 对应规则 |
|---|---|
| 跨色相渐变的按钮或文字 | A1 |
| 三种以上颜色 | A2 |
| 每行前面一个彩色方块图标 | A3 |
| 满屏粗体 | B1 |
| 一排三张统计小卡片 | C1 |
| 不必要的进度环 | C2 |
| 灰底上摞满白卡片 | D1 |
| 内容区的毛玻璃和光晕 | D3 |
| 并排的几个实底按钮 | E1 |
| 底部导航 + 顶部 Tab + 胶囊筛选同时出现 | F2 |
| 只有几项也做“全部 / 待办 / 已完成” | F2 |
| 标题或按钮里的表情 | G1 |
| 填空的插画、吉祥物、3D 物件 | G2 |
| 角落里的装饰圆、光斑 | G3 |
| “欢迎回来 ✨” | H1 |
