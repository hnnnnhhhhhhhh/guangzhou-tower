# 让弱模型稳定出好结果的总框架

草案 v0.1 · 回应千问实跑后的问题 · 只有方法，没有改代码

## 0 先看千问那张图错在哪

“新家入住采购”这一屏，字重和字号层级做得还行，问题集中在三处：

| 问题 | 图上的表现 | 属于哪一类 |
|---|---|---|
| 同一个事实说了四遍 | 标题下“已买 1”、摘要里“1/4 已入手”、圆环“25%”、筛选“已买 1” | 信息结构 |
| 满屏卡片 | 摘要、成员、每个商品都是白色大圆角卡，灰底上摞了七八张 | 信息结构 + 视觉规则 |
| 次要的事占了主位 | “邀请朋友一起买”占了第二大块，比商品清单还靠前 | 信息结构 |
| 底部两层浮层叠在一起 | 黑色“加入商品”和胶囊底栏同时浮在清单上，压住了第三个商品 | 信息结构 |
| 奇怪的颜色 | 蓝紫渐变按钮，和其余黑白灰毫无关系 | 视觉风格 |
| 三种主按钮 | 渐变“邀请”、黑色“加入商品”、黑色“全部”筛选 | 视觉风格 |
| 东拼西凑 | 圆环来自一种风格，渐变按钮来自另一种，胶囊底栏又是一种 | 来源混用 |

结论：**字体和间距这类“数”的问题，组件库已经帮它守住了。剩下的是三件组件库管不了的事：信息结构、整体风格、不许混用来源。** 下面三节分别讲。

## 1 总原则：一个应用只有一个来源

千问“从这儿拼一点、从那儿拼一点”，是因为没人告诉它不许拼。规则：

> **一个应用只选一个信息结构模板、一份风格文档。不许从第二个来源取任何东西。**

- 信息结构模板决定：有哪些屏、每屏放哪些信息、按什么顺序、主操作是什么。
- 风格文档决定：所有颜色、字体、圆角、容器、配图。
- 两者之间没有交集，所以也不会冲突。
- 想要的东西两份里都没有 → 不做，或者写进交付说明里“没做的”。

**检查**：每个颜色值必须出现在风格文档的配色表里；每个信息项必须出现在信息结构模板的清单里。出现了文档之外的 → 报错并指出是哪个。蓝紫渐变按钮在这一条下直接不通过。

## 2 用户的需求怎么拆（澄清）

### 2.1 拆成六个问题

一句话需求先拆成下面六栏。**能从原话里直接找到的才填，找不到就问，不许猜。**

| 栏 | 问什么 | 例：“做一个和朋友一起买家具的清单” |
|---|---|---|
| ① 核心动作 | 用户每次打开**亲手做**的那件事是什么？ | 勾掉买好的东西 ✅ 原话可推出 |
| ② 次要动作 | 偶尔做的事是什么？ | 加商品、邀请朋友 ✅ |
| ③ 主要对象 | 屏幕上反复出现的“东西”是什么？有哪些字段？ | 商品：名称、价格、数量、备注、图 ⚠️ 字段要确认 |
| ④ 几种身份 | 不同的人看到的东西一样吗？ | ❓ 要问：朋友能改清单吗，还是只能看？ |
| ⑤ 对象是不是拿来看的 | 用户会不会因为“长什么样”来选它？ | 是，家具 → 需要图 |
| ⑥ 气质 | 从固定的五个词里选 | ❓ 要问 |

### 2.2 怎么问

- 一次最多问 3 个，按上表从上往下挑空着的。
- 每个问题给 2–4 个选项加“其他”，选项写成用户听得懂的话，不写术语。
- 用户不答就用默认值，并在规格里标明“默认”：

  | 栏 | 默认值 |
  |---|---|
  | 几种身份 | 一种，所有人权限一样 |
  | 气质 | 利落 |
  | 对象字段 | 只用名称和一个数值 |

例：

> 我还需要确认两件事：
> 1. 朋友加入后能做什么？　A 和我一样能加、能勾　B 只能看　C 只能勾掉自己买的
> 2. 你希望它看起来是什么感觉？　A 安静素净　B 温暖居家　C 利落干脆　D 其他

### 2.3 这六栏直接决定后面的选择

- ① 核心动作 → 选哪个信息结构模板（第 3 节）
- ⑤ 是不是拿来看的 + ⑥ 气质 → 选哪份风格文档（第 4 节）

所以澄清不是客套，是后面两次“选择”的输入。这六栏填不满，后面一定会乱选。

## 3 信息结构：参考什么、怎么参考

### 3.1 结论：参考“流程”，不参考“单屏”

Mobbin 的 MCP 能搜完整流程（`search_flows`），一次给出一个产品完成一件事的全部屏幕，按顺序。之前跑过：搜“背单词复习”拿到了 CapWords 20 屏、Babbel 14 屏、Quizlet 7 屏的完整流程。

单屏截图只能告诉模型“这屏长什么样”；流程能告诉它“用户从哪来、到哪去、每一步看到什么”。信息结构的问题（重复、次要占主位、两个浮层）都是流程层面的问题，只看单屏学不到。

### 3.2 但不要让千问自己去看流程

看 20 张图、归纳出结构，这对弱模型太难，它会挑几张印象深的拼起来——就是现在的问题。

做法：**线下由强模型读流程，写成“信息结构模板”存库；线上千问只按核心动作查模板。**

### 3.3 信息结构模板长什么样

按“核心动作”建，不按行业建。一个模板对应一种动作，比如“勾清单”“逐题作答”“按天排程”“约时段”“随手记一笔”。每个模板包含：

```
模板：勾清单（共享）
适用：用户的核心动作是把一组东西逐个标记为“完成”

来源流程：
  - Todoist 共享项目（Mobbin 链接）
  - AnyList 购物清单（Mobbin 链接）
  - Splitwise 分账群组（Mobbin 链接）

屏 1：清单（首页）
  第一屏最大的是：清单本身
  从上到下：
    1. 标题 + 一行进度（“已买 1 / 4”）           必有
    2. 筛选：全部 / 待办 / 已完成                  必有
    3. 清单行：勾选框、名称、一行补充、数值       必有
    4. 合计                                         可选，放清单最下面
  主操作：加一项 —— 放在清单末尾的一行，或底部一个按钮，二选一
  不要放：邀请入口、成员列表、大号统计卡
  同一个事实只出现一次：进度只在标题下出现

屏 2：一项的详情
  ……

屏 3：成员与邀请
  从哪进：标题右侧的头像
  ……

流程：
  加一项：点“加一项”→ 输入名称 → 回车即加入，停留在清单（2 步）
  勾掉：点勾选框 → 这一行变灰、移到“已完成”（1 步）
```

### 3.4 规则（给千问的）

1. 按 2.1 的“核心动作”选**一个**模板。选不到合适的 → 用“通用列表”模板，并在交付说明里写“没有找到匹配的结构模板”。
2. 模板里“必有”的全部放；“可选”的默认不放，要放必须写出对应用户原话的哪一句。
3. 模板里“不要放”的一律不放。
4. 模板之外的信息一律不放。
5. 同一个事实一屏只出现一次。

**检查**：

- 每屏的信息项和模板逐项对比，多了、少了都报错。
- 同一个数在一屏出现两次以上（比如“1”在已买、1/4、筛选里都有）→ 报错“已买数量出现了 3 次，只保留标题下那一处”。
- 底部同时有浮动按钮和浮动导航 → 报错“底部只能有一层浮动元素”。

### 3.5 线下怎么建模板

1. 每种核心动作，用 `search_flows` 搜 3 个做得好的产品的完整流程。
2. 强模型逐屏读，写下每屏的信息项和顺序。
3. 三个产品取交集作“必有”，取并集减交集作“可选”，三个都没有但常被误加的写进“不要放”。
4. 设计师过一遍，签字入库。
5. 先做 10–15 个最常见的动作就够覆盖大部分需求。

## 4 视觉风格：用你的风格模板，但要补三样东西

### 4.1 你的模板方向是对的

它覆盖了配色、字体、间距、卡片、配图五个方面，而且要求写具体做法、不写形容词。这已经是一份好的“风格说明书”。

### 4.2 但弱模型用它会出三个问题

| 问题 | 原因 | 补什么 |
|---|---|---|
| 照着说明书还是会自己发明颜色 | 说明书是散文，模型读完记住的是印象，不是那几个色值 | **配色只许用表里的 8 个色，表外的色一律不许出现** |
| 不知道哪些事绝对不能做 | 模板只写了“要怎样”，没写“不要怎样” | **每份风格加一节“不要做”** |
| 读了说明书不知道落到哪个组件上 | 说明书和组件库之间没有对应关系 | **每份风格加一张“组件怎么设”的表** |

### 4.3 建议在模板末尾加三节

```markdown
## 07 不要做

（每份风格至少 5 条，写成具体做法。下面是这份风格的例子）
- 不用渐变。主按钮是主强调色的实底。
- 不把清单的每一行包成卡片。清单行之间用细线分隔。
- 不用阴影。
- 一屏最多一个实底主按钮。
- 不用配色表之外的颜色，包括状态色之外的任何彩色。

## 08 组件怎么设

| 组件 | 这份风格里的设置 |
|---|---|
| 页面背景 | 页面底色 |
| 清单 | 不加外框，行与行之间用边框色细线，行高 56 |
| 卡片 | 只给“能单独拿走的一个东西”用；卡片底色、圆角 12、无边框、无阴影 |
| 主按钮 | 主强调色实底、主按钮文字色、圆角 12、高 48 |
| 次按钮 | 无底色、1px 边框色描边、主要文字色 |
| 输入框 | 卡片底色、无边框、圆角 12 |
| 选中的标签 | 主要文字色实底、页面底色文字 |
| 未选中的标签 | 无底色、辅助文字色 |
| 底部导航 | 页面底色、顶部一条细线、不浮动 |

## 09 对照图

- 对：（一张按这份风格做出来、设计师认可的截图）
- 错：（一张常见的错误做法，标出错在哪）
```

第 08 节是关键：它把“风格”翻译成了“组件的参数”，千问不用理解风格，只要照表设参数。

### 4.4 风格文档谁来写

**不要让千问从参考图里提炼风格。** 看图提炼是这条链路里最需要眼光的一步，弱模型做不好，做不好就会出现奇怪的颜色。

做法：

1. **线下**：强模型对着 Mobbin 上 3–5 张同一个产品的高清图，按你的模板填一份风格文档初稿。色值用脚本从图上量，不目测。
2. **设计师**改初稿，补“不要做”和对照图，签字入库。
3. 先建 8–12 份风格，覆盖五种气质 × 有图 / 无图。
4. **线上**：千问按两个标签选一份——气质（来自澄清第 ⑥ 栏）和有没有图（来自第 ⑤ 栏）。

### 4.5 选风格的规则（给千问的）

```
如果 对象是拿来看的 且 能拿到真图：只能选标了“靠图”的风格
如果 对象不是拿来看的 或 拿不到真图：只能选标了“不靠图”的风格
在剩下的里面，选气质标签和用户选的一致的
还有多个：选列表里排在最前的那个
一个都没有：用“默认风格”，并在交付说明里写明
```

### 4.6 要不要加图

| 对象是拿来看的吗 | 能拿到真图吗 | 怎么做 |
|---|---|---|
| 是（家具、菜、景点、商品、作品、人） | 能 | 每个对象一个图位，用对象名去搜图，核对是不是这个东西 |
| 是 | 不能 | 留图位，显示“暂无图片”，允许用户自己上传 |
| 不是（题目、待办、时段、金额、打卡） | — | 不加图位 |

不许用表情、图标、色块代替内容图。生成的图不能用来表示具体的东西。

## 5 细节问题：能用规则解决的都写成可检查的规则

你提的几条，都可以写成“如果…就…”，并且都能用脚本查。已经写进 `docs/design-details.md` 的标了“已有”。

| 规则 | 怎么查 | 状态 |
|---|---|---|
| 不要满屏卡片：同类的一组东西是清单，不是一组卡片 | 数一屏里带底色或阴影的块，超过 3 个报错 | 要新做 |
| 区块之间用留白或细线分开，不用卡片 | 同上 | 要新做 |
| 日期分三段，分隔符小一档 | 查界面文字里整段的“数字/数字” | 已有规则，检查要新做 |
| 货币符号、单位比数字小一档，基线对齐 | 查大号数字旁同字号的 ¥、%、件 | 已有规则，检查要新做 |
| 圆角嵌套同心：里层 = 外层 − 间距 | 量父子元素的圆角和间距 | 已有规则，检查要新做 |
| 一块东西只用一种方式和背景分开 | 同一元素既有边框又有阴影就报错 | 已有 |
| 粗体稀缺，不用最粗的两档 | 统计字重 | 已有 |
| 一屏一种字体 | 统计衬线与无衬线 | 已有 |
| 不要出现一行只有一个字 | 量每段文字最后一行的宽度，只有一个字就报错 | 要新做 |
| 同一个事实一屏只出现一次 | 找同一屏里重复出现的数字和短语 | 要新做 |
| 一屏最多一个实底主按钮 | 数实底按钮 | 要新做 |
| 底部最多一层浮动元素 | 数底部固定或浮动的元素 | 要新做 |
| 不用配色表以外的颜色，不用渐变 | 取所有计算后的颜色和背景，和配色表比对 | 要新做 |

**报错要写成改法**，例如“‘已买 1’出现了 3 次（标题下、摘要、筛选）：只保留标题下那一处”。弱模型按明确的改法能改对，按“信息重复”这种描述改不对。

## 6 整条链路

```
用户一句话
  │
  ├─ 澄清（第 2 节）：填六栏，缺的问，最多 3 个问题
  │
  ├─ 选信息结构模板（第 3 节）：按“核心动作”从库里选一个
  │
  ├─ 选风格文档（第 4 节）：按“气质 + 有没有图”从库里选一份
  │
  ├─ 生成：只用组件库；组件参数照风格文档第 08 节设；信息照模板放
  │
  ├─ 检查（第 5 节 + 第 1 节）：不通过就按“改法”改，最多三轮
  │
  └─ 交付：写明用了哪个模板、哪份风格、哪些是默认值、哪些没做
```

**千问在线上只做三种事**：问用户问题、从库里选、按表填。没有一步需要它看图或者发挥审美。

**需要眼光的事全在线下**：读流程写结构模板、读参考图写风格文档、设计师签字。这是一次性的投入，之后持续补充。

## 7 先做什么

按投入产出排：

1. **给你现有的风格模板补第 07、08、09 节**，先拿一两份现有风格试，看千问能不能照着第 08 节把组件设对。这一步最便宜，可能就能解决“奇怪的颜色”和“不能细看”。
2. **加第 1 节和第 5 节的检查**：只用一个来源、颜色只能来自配色表、满屏卡片、重复信息、一行一个字。这些全是脚本，不依赖模型能力。
3. **改澄清**：按第 2 节的六栏和问法。
4. **建信息结构模板库**：先挑你们需求里最常见的 5 个核心动作，每个用 Mobbin 流程做一份。这一步投入最大，但解决的是现在最明显的问题。
5. **建风格文档库**：8–12 份，设计师签字。

---

## 8 我不确定的

- **第 3、4 节的库需要多少份才够用**，要看你们用户需求的分布。先按最常见的做，跑一段时间看“没有匹配模板”的比例。
- **Mobbin 的内容提炼后用在你们的产品里**，授权上是否允许，需要你们确认。文档里只存文字提炼和链接，不存截图，会稳妥一些。
- **千问照着第 08 节的表设组件参数能不能设对**，没有实测过。这是最值得先验证的一步。
- **“一行一个字”的检查**在中英混排时可能误报，要调。
