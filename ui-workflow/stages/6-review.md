# 阶段 6 · 评审与修正

**输入** `out/<screen>.light.png`、`out/<screen>.dark.png`、spec、`style/DESIGN.md`、`refs/patterns.json`
**产物** `out/review-<screen>.json`

门禁管的是对错，这一步管的是好坏。**需要能看图的模型；最好不是搭这一屏的那个模型**——自己评自己的产出，分数会偏高。

## 评分表

每项 0 / 1 / 2 分，每项必须写一句看得见的依据（指到截图上的具体位置）。说不出依据的给 0。

| # | 项目 | 2 分的样子 |
|---|---|---|
| 1 | 主操作 | 一眼能找到，全屏只有它用了最强的强调 |
| 2 | 层级 | 眯眼看能分出三层：最重要 / 次要 / 辅助，且和 spec 的 priority 一致 |
| 3 | 信息预算 | 没有“放了也没人看”的元素；每个区都在服务 brief 的某条任务 |
| 4 | 间距节奏 | 区与区的间距明显大于区内间距；同级元素间距相等；边距对齐 |
| 5 | 风格符合 | DESIGN.md 的每条规则逐条核对，全部符合 |
| 6 | 结构有据 | 框架和各区的做法能对上 patterns 的 decisions |
| 7 | 真实内容 | 长文本、0、大数都没有把版面撑坏或截得看不懂 |
| 8 | 明暗一致 | 暗色下层级关系和亮色相同，没有消失的边界或刺眼的色块 |

另外单独回答一个是非题：**这屏会不会被认成某一个参考 app？** 会的话直接不通过，回阶段 4 换掉最像的那个结构决定。

## 通过线

总分 ≥ 13 且没有任何一项是 0。

## 不通过时

把扣分项写成具体的修改指令（“把‘还剩 2 个’移到进度条下方左对齐”，而不是“优化层级”），交回阶段 5 修改 → 重跑门禁 → 重新评审。最多 3 轮；3 轮还不过，停下来把截图和三轮评审交给用户，不要继续磨。

## 输出格式

```json
{
  "screen": "today",
  "round": 1,
  "reviewer": "<模型名>",
  "scores": [{"item": 1, "score": 2, "evidence": "…"}],
  "total": 14,
  "resembles_single_reference": false,
  "pass": true,
  "fixes": []
}
```
