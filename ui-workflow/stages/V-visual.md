# 阶段 V · 视觉

**输入** 风格参考的**高清**截图（`style/shots/`，同一个 app 的 3–8 张）
**产物** `style/VISUAL.md`、（需要时）`style/visual.css`、用配方搭出来的屏

结构可以从低清图里读出来，视觉不行。阴影、模糊、细线、字重这些信息只在高清图里有：用结果里的 `image_url` 下载原图（1180 像素宽左右），放大到局部看。

## V1 读视觉 → `style/VISUAL.md`

把参考图放大，逐项回答，每条注明是从哪张图的哪个位置看出来的：

| 项 | 要回答的问题 |
|---|---|
| 底 | 页面底色是纯白、带灰、还是带色调？有没有渐变或远处的色团？ |
| 面 | 卡片和底怎么分开：阴影（几层、多散）、描边、还是只靠明度差？圆角多大？ |
| 层 | 有没有浮在内容上方的东西？它是实色、半透明还是毛玻璃？内容滑到它下面时是被切掉还是渐隐？ |
| 字 | 最大的字多大、多重？标题有没有特别的处理（两种灰度、两种字重叠在一起）？次级文字靠变小还是变灰？ |
| 色 | 彩色出现在哪、面积多大？是实色块、浅色底、还是虚线描边？ |
| 形 | 标签、按钮、输入框各是什么形状？有没有重复出现的特殊形状？ |
| 动 | 能从流程截图里推断出的转场：浮起、展开、翻转？ |
| 记忆点 | 这个 app 最让人记住的 1–3 个画面处理是什么？ |
| 素材 | 插画、3D、照片、表情——哪些是做不出来、必须由人提供或另行生成的？ |

## V2 对到配方

`recipes/` 是视觉配方库：每个配方是参考图里的一种做法，带真实的样式实现。屏幕文件**只组合配方、填参数**，不自己写样式。

1. 先看现有配方（`recipes/index.tsx`）能不能表达 VISUAL.md 里的每一条。
2. 只是数值不同（颜色、圆角、阴影深浅）：在 `style/visual.css` 里覆盖 `recipes.css` 开头那组变量。
3. 确实缺一种做法：往 `recipes/` 里加一个新配方（组件 + 样式），在 VISUAL.md 里记下它对应参考图的哪一处。**新增配方属于改工作流，需要人看过**——这是设计师介入的位置。
4. 素材类的缺口不要用色块假装，如实列在 VISUAL.md 的“素材”一节。

## 版式规范（配方必须遵守，门禁会查）

好看的前提是整齐。规范来自组件库的刻度，配方只在它上面加材质。

- **间距**只取 Astryx 的 `--spacing-*`（4px 一档）。常用的已经起了名字：屏幕边距 20、卡片内边距 24、卡内块间距 16、卡与卡 16、区与区 32、同类小元素 8、主副文字 4。
- **所有卡片用同一个内边距**，这样不同卡片里的文字左缘在一条线上。
- **层级关系**：组内间距 < 卡片内边距 < 区间距。反过来就会显得散。
- **字阶七档**（13 / 15 / 17 / 20 / 28 / 44 / 56），字号和行高成对使用，不单独改其中一个。
- **控件高度三档**：胶囊 32 / 40，可点的东西至少 44，主按钮 56。
- **圆角**只取 `--radius-*`：卡片 28、卡内元素 12、胶囊全圆。
- 卡片里的东西是平的：不在卡片里再叠阴影。

`recipes.css` 里，这些数只在开头的 `:root` 里定义一次；`:root` 之外写死任何间距、字号、圆角、高度，门禁的 `tokens` 检查都会报错。要调整某个风格的松紧，在 `style/visual.css` 的 `:root` 里覆盖变量，而不是去改单个配方。

## V3 每屏一个记忆点

对照 `app-spec.json` 里每屏的 `signature`。没有记忆点的屏是线框图。记忆点应该服务这一屏的主操作（背单词那屏的记忆点是那张卡本身），而不是装饰。

## V4 并排评审

把产出的截图和参考图拼在一起看，按上表前六项各打 0–2 分（2 = 放在一起不违和，1 = 方向对但粗糙，0 = 没做出来）。素材单独记，不计入。满分 12，**≥ 9 才算达到参考的七成**。评审者要能看图，最好不是搭建者。
